# Deploying LUCID-PD

The whole system (React interface, FastAPI service, both models, the SHAP explainer, the
guidance corpus) runs as one container on **Hugging Face Spaces**, using the Docker SDK.
One platform, one repository, one URL. Nothing else has to be hosted separately.

## Why this platform

The prototype needs a long-running Python process with roughly 3 GB of image, native
libraries (openSMILE, ffmpeg, libsndfile), a 94 MB PyTorch checkpoint and a browser client
served over HTTPS so the microphone works. Static hosts and serverless functions cannot
hold that. Hugging Face Spaces runs it on shared CPU hardware alongside the model
artefacts, and gives a citable URL suited to an academic deliverable. The image is a
standard Dockerfile, so the same container runs unchanged on any container host if the
project later moves.

## What you need

| Requirement | Detail |
| --- | --- |
| Hugging Face account | An account holding a paid plan. Hugging Face permits only static Spaces on free personal accounts, so creating a Docker Space returns HTTP 402 until the owning account is upgraded, or unless it is an organisation on a Team or Enterprise plan. |
| Write token | huggingface.co → Settings → Access Tokens → **Create new token**, type *Write*, on the account that owns the Space. Needed once, to push. |
| Space hardware | **CPU basic**, 2 vCPU and 16 GB. No GPU is required or usable here. |
| Model artefacts | `models/deployed_voice.joblib` and `models/deployed_mri.pt` present locally. Rebuild with `python -m pdcdss.speech.deploy_voice` and `python -m pdcdss.mri.deploy_mri`. |
| Python packages | `huggingface_hub` on the machine doing the push (`pip install huggingface_hub`). |
| Space secret (optional) | `HF_TOKEN`, which switches the explanation layer from the deterministic grounded summary to generated text. See below. |

Nothing else is needed. There is no database, no object storage, no separate frontend
host, no Ollama server and no paid inference endpoint.

## Deploying

```bash
pip install huggingface_hub
hf auth login                                   # paste the write token
python scripts/deploy_space.py --repo nkeseeyo/lucid-pd-cdss --private
```

The script rebuilds `build/hf_space/` from the project, then creates the Space and uploads
it. Hugging Face builds the image on push, which takes roughly ten minutes the first time,
after which the Logs tab reads *Running* and the app is live at
`https://huggingface.co/spaces/nkeseeyo/lucid-pd-cdss`.

Re-run the same command to redeploy after any change. Drop `--private` once the build and
the disclaimers have been checked, or flip visibility in the Space settings, and use
`--stage-only` to inspect `build/hf_space/` without uploading anything.

## The explanation layer

The container sets `SLM_BACKEND=hf`, so the grounded explanation is generated by
`Qwen/Qwen3-4B-Instruct-2507` through Hugging Face Inference Providers, using the same
system prompt, retrieved guideline text and faithfulness guardrail as the RQ3 evaluation.
This requires `HF_TOKEN` as a **Space secret**, set under Settings → Variables and secrets.

Without that secret the service still answers every request, returning a deterministic
summary that states the probability, the risk band, the SHAP feature families and the
retrieved guideline text verbatim. The prediction, the evidence and the care route are
unaffected; only the generated paragraph is absent.

`SLM_BACKEND=ollama` is the local development setting, reaching a local daemon exactly as
the evaluation did, and `SLM_BACKEND=off` disables generation entirely.

## What runs where

```text
huggingface.co/spaces/nkeseeyo/lucid-pd-cdss   one Docker container, port 7860
  /                     compiled React interface (served by the API, same origin)
  /docs                 interactive API documentation
  /health               liveness check
  /predict/voice        eGeMAPS -> XGBoost -> SHAP -> explanation -> care route
  /predict/mri          ResNet-50 -> Grad-CAM overlay (flagged research baseline)
  /predict/combined     decision-level combination of the two (illustrative)
```

Uploads are written to a temporary directory and deleted as soon as the response is built,
so no recording or image is retained.

## Verifying a deployment

```bash
curl https://nkeseeyo-lucid-pd-cdss.hf.space/health
curl -X POST -F "file=@recording.wav" https://nkeseeyo-lucid-pd-cdss.hf.space/predict/voice
```

To reproduce the container locally before pushing:

```bash
python scripts/deploy_space.py --repo nkeseeyo/lucid-pd-cdss --stage-only
docker build -t lucid-pd-space build/hf_space
docker run --rm -p 7860:7860 -e HF_TOKEN=hf_... lucid-pd-space
```

## Files

| Path | Role |
| --- | --- |
| `deploy/hf_space/Dockerfile` | Two-stage build: Node compiles the interface, Python serves it with the API |
| `deploy/hf_space/requirements.txt` | Runtime dependencies, with scikit-learn and xgboost pinned to the versions that produced the serialised model |
| `deploy/hf_space/README.md` | The Space landing page, including its YAML configuration header |
| `scripts/deploy_space.py` | Stages the project into `build/hf_space/` and uploads it |
